# jma-alert-map

気象庁の地震情報を取得し、Power BI の地図上に可視化するための最小構成キットです。
Azure などのクラウド環境を使わず、Windows の標準機能と Power BI Desktop のみで動作します。

---

## これは何をするものか

1. 気象庁が公開している地震情報の JSON を取得する
2. 震源座標（ISO 6709 形式）を緯度・経度・深さに分解する
3. ローカルの CSV に履歴として追記する（重複・続報は自動で整理）
4. Power BI Desktop がその CSV を読み、地図上に震源をプロットする

将来的に Azure SQL や Fabric へ移行する際も、CSV の列構成をそのままテーブル定義に転用できるよう設計しています。

---

## 動作要件

| 項目 | 要件 |
| --- | --- |
| OS | Windows 10 / 11 |
| PowerShell | 5.1 以上（Windows 標準のままで可） |
| Power BI Desktop | 任意の最新版 |

## フォルダ構成

```
jma-alert-map/
├── README.md                    このファイル
├── ingest/
│   ├── Fetch-JmaQuake.bat       ← 気象庁の取得はこれをダブルクリック
│   ├── Fetch-JmaQuake.ps1       気象庁の取得・整形・CSV追記を行う本体
│   ├── Fetch-UsgsQuake.bat      ← USGS(全世界)の取得はこれをダブルクリック
│   ├── Fetch-UsgsQuake.ps1      USGS の取得・整形・CSV追記を行う本体
│   ├── Register-Task.bat        ← 定期実行の登録はこれをダブルクリック
│   ├── Register-Task.ps1        タスクスケジューラへ定期実行を登録
│   ├── Unregister-Task.bat      ← 定期実行の解除はこれをダブルクリック
│   └── Unregister-Task.ps1      登録した定期実行を解除
├── powerbi/
│   ├── phase0_direct.pq         気象庁JSONを直接読む（履歴なし・お試し用）
│   ├── phase1_csv.pq            気象庁のCSVを読む（日本のみ）
│   └── phase2_combined.pq       気象庁 + USGS を統合（全世界・推奨）
└── data/
    ├── events.sample.csv        列構成の見本。Power BI の接続確認用
    ├── events.csv               気象庁のデータ（実行すると生成）
    ├── events_usgs.csv          USGS のデータ（実行すると生成）
    ├── fetch.log                実行記録。1MB を超えると自動で退避される
    └── fetch.log.old            退避された過去のログ（発生時のみ）
```

`.ps1` は処理の本体、`.bat` はそれを起動するための入口です。
**操作はすべて `.bat` のダブルクリックで完結します。**
`.ps1` を直接実行する必要はありません（実行ポリシーの設定が必要になるためです）。

## 使い方

### 手順 1. 取得スクリプトを一度手動で実行する

`ingest\Fetch-JmaQuake.bat` をダブルクリックしてください。

成功すると `data\events.csv` が生成され、取得件数が表示されます。

この `.bat` は PowerShell の実行ポリシーをそのプロセス内でのみ回避するもので、
PC の設定は変更しません。**通常はこれだけで動きます。**

PowerShell から直接実行したい場合は次のようにします。

```powershell
cd <このフォルダ>\ingest
.\Fetch-JmaQuake.ps1
```

この場合、後述の実行ポリシーの設定が必要になることがあります。

### 手順 2. 海外の地震も取得する（任意）

全世界を対象にする場合は、`ingest\Fetch-UsgsQuake.bat` もダブルクリックしてください。
`data\events_usgs.csv` が生成されます。

日本国内だけで足りる場合、この手順は不要です。手順 3 へ進んでください。

### 手順 3. 定期実行を登録する

`ingest\Register-Task.bat` をダブルクリックしてください。次の 2 つが登録されます。

| タスク名 | 対象 | 既定の間隔 |
| --- | --- | --- |
| JMA Quake Ingest | 気象庁 | 15 分 |
| USGS Quake Ingest | USGS（全世界） | 60 分 |

間隔を変更する場合は、PowerShell から次のように実行します。

```powershell
.\Register-Task.ps1 -IntervalMinutes 30 -UsgsIntervalMinutes 180
```

気象庁のみを登録したい場合は `-SkipUsgs` を付けてください。

解除する場合は `ingest\Unregister-Task.bat` をダブルクリックしてください。
両方のタスクが解除されます。蓄積済みの CSV は削除されません。

### 手順 4. Power BI Desktop に接続する

1. Power BI Desktop を起動する
2. リボンの「データを取得」→「空のクエリ」を選択する
3. 「詳細エディター」を開く
4. 次のいずれかの中身をすべて貼り付ける

   | ファイル | 対象 |
   | --- | --- |
   | `powerbi\phase2_combined.pq` | 気象庁 + USGS（**推奨**） |
   | `powerbi\phase1_csv.pq` | 気象庁のみ（日本国内だけで足りる場合） |

5. 先頭付近の `DataFolder` が、このキットの `data` フォルダの絶対パスになっていることを確認する
   （別の PC に渡した場合はここを書き換えます）
6. 「閉じて適用」を押す

### 手順 5. 地図を作る

1. 視覚化ペインから地図ビジュアルを選択する

   | ビジュアル | 使えるか |
   | --- | --- |
   | **マップ**（標準搭載のバブルマップ） | 多くの環境で利用可。**まずこれを試してください** |
   | Azure Maps | 組織のテナント設定で無効化されている場合があります |

   Azure Maps が視覚化ペインに出ない、または使用できない旨が表示される場合は、
   標準の「マップ」を使ってください。以降の割り当ては共通です。

2. 各フィールドに以下を割り当てる

| ビジュアルの項目 | 割り当てる列 |
| --- | --- |
| 緯度 | `lat` |
| 経度 | `lon` |
| バブルサイズ | `magnitude` |
| 凡例 | `intensity_label`（または `region` / `source`） |
| ツールヒント | `hypocenter`, `occurred_at_jst`, `depth_km` |

**必ず行ってください**：フィールドウェルに入れた `lat` と `lon` の `∨` をクリックし、
**「集計しない」** を選択します。

既定では合計または平均で集計されるため、この設定を行わないと
**すべてのイベントが 1 点にまとまって表示されます**。
地図にバブルが 1 つしか出ない場合は、ほぼこれが原因です。

3. 凡例に `intensity_label` を使う場合は、「列で並べ替え」で `intensity_rank` を
   指定してください。指定しないと辞書順（震度 1, 震度 2, 震度 5-, …）になります。

**最初に確認すべきこと**：震源が海域のイベント（宮城県沖、千葉県東方沖など）で、
点が正しく海上に落ちているかを目視してください。
ここが合っていれば座標の処理は正しく機能しています。

### 手順 6. スライサーとデータ範囲の表示を追加する

期間・地域での絞り込みと、データ範囲の表示を追加します。
詳細は後述の「期間・地域で絞り込む」を参照してください。

## データの保持期間

**気象庁が公開している一覧には、直近およそ 30 日分のイベントのみが含まれます。**
それより古いものは順次削除されていきます。

したがって、初回の実行で得られるのは 30 日分だけです。
ただし定期実行を登録しておけば、消える前に取り込んで手元に蓄積されるため、
**運用を続けるほど履歴は 30 日を超えて伸びていきます。**
これが、気象庁の JSON を直接読まずに CSV を挟んでいる理由です。

USGS 側は既定で過去 30 日分を取得しますが、`-Days` を指定すれば
より長い期間をさかのぼって一括取得できます（最大 365 日）。

```powershell
.\Fetch-UsgsQuake.ps1 -Days 365 -MinMagnitude 5.5
```

現在どの期間のデータが読み込まれているかは、後述の `表示範囲` メジャーで
レポート上に常時表示できます。

## 海外の地震を含める

気象庁が海外の地震を発表するのは、日本に影響が及ぶ規模のものに限られます
（実測では 30 日間で 3 件程度）。
全世界を対象にする場合は USGS を併用してください。

1. `ingest\Fetch-UsgsQuake.bat` をダブルクリックする
2. `data\events_usgs.csv` が生成される
3. Power BI 側のクエリを `phase2_combined.pq` に差し替える

既定では **マグニチュード 4.5 以上・過去 30 日** を取得します。
全世界の地震は M2.5 以上まで含めると年間 3 万件を超えるため、
既定値を下げる場合はデータ量に注意してください。
変更するには `Fetch-UsgsQuake.bat` の中の `-MinMagnitude` の値を書き換えます。

### 重複の除去について

同じ地震が気象庁と USGS の双方に現れます。
`phase2_combined.pq` は、**発生時刻が 120 秒以内かつ震源が 100km 以内**の
イベントを同一とみなし、USGS 側を除外して気象庁のレコードを残します。

距離のしきい値を大きめに取っているのは、USGS の速報値が
気象庁の確定値と数十 km 程度ずれるためです。
しきい値は `phase2_combined.pq` の `TimeToleranceSec` と
`DistanceToleranceKm` で調整できます。

## 期間・地域で絞り込む

`phase2_combined.pq` は、スライサーに使える列をあらかじめ用意しています。

| 列名 | スライサーの用途 | 備考 |
| --- | --- | --- |
| `occurred_date` | 期間の絞り込み | スライサーの書式を「相対日付」にすると「過去7日間」などが選べます |
| `region` | 地域の絞り込み | 日本 / アジア / オセアニア / 北米 / 中南米 / 欧州・中東・アフリカ / その他 |
| `source` | 情報源の絞り込み | JMA / USGS |
| `magnitude_band` | 規模の絞り込み | M7.0以上 / M6.0-6.9 / … |
| `intensity_label` | 震度の絞り込み | `intensity_rank` で並べ替えると震度順になります |

地域の分類は緯度経度の矩形による粗いもので、厳密な国境ではありません。
分類を変更する場合は、`Fetch-JmaQuake.ps1` と `Fetch-UsgsQuake.ps1` の
両方にある `Get-Region` 関数を編集してください（内容を揃える必要があります）。

### データ範囲をレポートに表示する

「いつまでのデータが入っているか」が一目で分かるよう、
次のメジャーを作成してカードビジュアルに配置することを推奨します。

```dax
表示範囲 =
    "表示範囲: "
    & FORMAT(MIN('events'[occurred_at_jst]), "yyyy/MM/dd")
    & " 〜 "
    & FORMAT(MAX('events'[occurred_at_jst]), "yyyy/MM/dd")
```

```dax
最終取得 = "最終取得: " & FORMAT(MAX('events'[fetched_at_jst]), "yyyy/MM/dd HH:mm")
```

`'events'` の部分は実際のクエリ名に合わせてください。

**`最終取得` は必ず配置してください。**
取得に失敗していても地図には前回までのデータが表示され続けるため、
これが無いと「地震が起きていない」のか「取得できていない」のかを区別できません。

## 出力される列

| 列名 | 型 | 内容 |
| --- | --- | --- |
| `event_id` | 文字列 | 地震の識別子。続報が来ても同一値 |
| `report_no` | 整数 | 続報の通番。大きいほど新しい |
| `info_type` | 文字列 | 情報の種類（震源・震度情報 など） |
| `hypocenter` | 文字列 | 震源地名 |
| `occurred_at_utc` | 文字列 | 発生時刻（UTC, ISO 8601） |
| `published_at_utc` | 文字列 | 発表時刻（UTC, ISO 8601） |
| `lat` | 数値 | 緯度（10進度・WGS84 相当） |
| `lon` | 数値 | 経度（10進度・WGS84 相当） |
| `depth_km` | 数値 | 深さ（km、正の値） |
| `magnitude` | 数値 | マグニチュード |
| `max_intensity` | 文字列 | 最大震度（`5-` `6+` などの表記） |
| `intensity_rank` | 整数 | 震度の並べ替え用キー（1〜9） |
| `area_code` | 文字列 | 気象庁の震央地名コード |
| `source` | 文字列 | 情報源（`JMA` / `USGS`） |
| `region` | 文字列 | 地域区分（緯度経度による粗い分類） |
| `fetched_at_utc` | 文字列 | このレコードを取得した時刻 |

USGS のレコードには気象庁震度に相当する項目がないため、
`max_intensity` と `intensity_rank` は空になります。

時刻を UTC で保持しているのは、将来 GDACS や USGS など海外のソースを併用する際に
タイムゾーンの取り違えを防ぐためです。表示用の日本時間は Power Query 側で生成しています。

## 設計上の要点

### 震源座標の分解

気象庁の JSON では、震源座標が `+32.7+130.7-10000/` のような
ISO 6709 形式の 1 つの文字列として格納されています。
符号が区切り文字を兼ねているため、単純な文字列分割では正しく処理できません。
本スクリプトでは正規表現で符号を境に切り出しています。

深さは負のメートル値で入るため、正の km 値に変換しています。

### 重複と続報の扱い

同じ地震に対して続報（`report_no`）が複数回発表されます。
本スクリプトは `event_id` を主キーとし、`report_no` が最大のレコードのみを保持します。
そのため何度実行しても CSV が重複で膨らむことはありません。

### 履歴について

気象庁が公開している一覧には直近のイベントのみが含まれ、古いものは順次消えていきます。
定期実行を登録しておくことで、消える前に取り込んで手元に履歴を蓄積します。
これが `phase0_direct.pq`（直接読み）ではなく CSV を挟む理由です。

### アクセス頻度

取得先は一般に公開されている静的 JSON ですが、公式に API として提供されているものではありません。
取得間隔は 15 分程度から始め、必要に応じて調整してください。極端に短い間隔での実行は避けてください。

## うまく動かないとき

### 「スクリプトの実行が無効になっているため…」と表示される

PowerShell の既定はスクリプト実行が禁止されているため、`.ps1` を直接実行すると発生します。

1. **`ingest\Fetch-JmaQuake.bat` を使う** — PC の設定を変えずに済むため、これが最も簡単です
2. PowerShell から直接実行したい場合は、次を一度だけ実行します（管理者権限は不要で、現在のユーザーにのみ適用されます）

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

上記を実行しても解消しない場合は、グループポリシーで実行ポリシーが固定されている可能性があります。
次のコマンドで確認してください。

```powershell
Get-ExecutionPolicy -List
```

`MachinePolicy` または `UserPolicy` が `Undefined` 以外になっている場合は組織の設定で固定されており、
`.bat` による回避も含めて利用者側では変更できません。システム管理部門に相談してください。

### 「ファイルはブロックされています」と表示される

ネットワーク経由で取得したファイルに付与される識別子が原因です。次のコマンドで解除できます。

```powershell
Get-ChildItem <このフォルダ> -Recurse | Unblock-File
```

### 「Unexpected token」「The string is missing the terminator」などの構文エラーが出る

スクリプトの構文ではなく、**ファイルの文字コード**が原因です。

Windows PowerShell 5.1 は、BOM のない UTF-8 ファイルを Shift-JIS として読み込みます。
その結果、日本語のコメントが正しく解釈されず、後続の行を巻き込んで構文エラーになります。

本キットの `.ps1` は **BOM 付き UTF-8** で保存されています。
スクリプトを編集する場合は、この文字コードを維持してください。
エディタで「UTF-8（BOM 付き）」を選択して保存すれば問題ありません。
VS Code の場合、右下の文字コード表示から `UTF-8 with BOM` を指定します。

### 文字が化ける

`data\events.csv` は BOM 付き UTF-8 で出力されます。
Excel で開いて化ける場合は、テキストエディタで文字コードを確認してください。
Power BI 側は `phase1_csv.pq` / `phase2_combined.pq` で UTF-8 を明示しているため、
通常は問題ありません。

### 地図にバブルが 1 つしか表示されない

`lat` と `lon` が集計されています。
フィールドウェルでそれぞれの `∨` をクリックし、**「集計しない」** を選択してください。

### 地図に一部のイベントしか表示されない

地図ビジュアルには描画できるデータポイント数の上限があります
（標準の「マップ」はおよそ 3,500 点）。
履歴が蓄積されて上限を超えると、一部が間引かれます。

期間スライサー（`occurred_date`）や規模スライサー（`magnitude_band`）で
初期表示を絞ってください。運用上も、全期間を一度に表示する必要はほとんどありません。

### Azure Maps ビジュアルが選択できない

組織のテナント設定で無効化されています。標準の「マップ」ビジュアルで代替してください。
フィールドの割り当ては同じです。

管理部門に問い合わせる場合、テナント設定では
**「Azure Maps ビジュアル」** と **「マップとコロプレス マップのビジュアル」** が
別項目である点を伝えると話が早く進みます。

## 注意事項

- **本キットは状況把握を目的とした補助的なツールです。** 人命に関わる判断の唯一の情報源としないでください。緊急地震速報など即時性が求められる情報は、公式の受信手段を併用することを前提としてください。
- 取得に失敗した場合、CSV は前回の内容のまま更新されません。`data\fetch.log` に実行結果が記録されるため、定期的に確認してください。
- 気象庁の公開データの利用にあたっては、同庁が示す利用条件を確認してください。
