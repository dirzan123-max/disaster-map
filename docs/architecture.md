# 設計メモ

作るときに迷った点と、なぜその形にしたかを残しておく。

---

## 出発点

もとは職場で「災害の発生を捉えて、地図で示したい」という話があり、
Power BI + PowerShell で作ったものが `re/`（jma-alert-map）にある。
あれは Windows と Power BI Desktop が前提で、担当者が席にいないと見られない。

BCP の用途では **持ち歩けること**と**自動で気づけること**が要るので、
アプリ／Web として作り直したのがこのリポジトリになる。

---

## 1. 全ソースを1つのモデルへ正規化する

`DisasterEvent`（`lib/domain/disaster_event.dart`）に寄せている。
地図・一覧・通知・Webhook は、元の API の形を一切知らない。

これで新しい取得先を足すときの作業が「Source クラスを1つ書く」だけになる。
逆に、正規化しきれない情報（気象庁の細分区域ごとの詳細など）は
`details` という文字列リストに逃がし、モデルを肥大させないようにした。

### 深刻度は 0〜4 の共通スケールに写像する

震度・マグニチュード・警報の種類・噴火警戒レベルは、そのままでは比較できない。
`Severity`（`lib/domain/severity.dart`）で 5 段階に揃えている。

| | 日本 | 世界 |
|---|---|---|
| 4 重大 | 特別警報 / 震度6弱以上 / 大津波警報 / 居住地域に及ぶ噴火警報 | M7.0以上 |
| 3 警戒 | 警報 / 震度5弱・5強 / 津波警報 / 入山危険 | M6.0以上 / 火山・洪水 |
| 2 注意 | 注意報 / 震度3・4 / 津波注意報 / 火口周辺警報 | M4.5以上 / 暴風・山火事 |
| 1 軽微 | 震度1・2 | M4.5未満 |
| 0 情報 | 解除など | — |

**この表がアプリ内の唯一の基準**で、地図の色・凡例・通知しきい値がすべてこれを見る。
利用者が「赤は何を意味するか」を一度覚えれば済むようにするため。

## 2. 座標を持たない情報をどう扱うか

気象庁の警報は「区域」、噴火警報は「火山」、津波予報は「予報区」で発表され、
**応答に座標が入っていない**。地図に出すには座標が要る。

| 情報 | やったこと |
|---|---|
| 気象警報 | 気象庁が公開している一次細分区域のポリゴン（`geojson/class10s.json`）から代表点を計算し、143件をアプリに同梱 |
| 噴火警報 | 気象庁の火山一覧（`volcano_list.json`）に座標があるので、117件をそのまま同梱 |
| 津波予報 | 予報区の代表点が手に入らないため、**地図には出さず一覧にだけ出す** |

代表点は「最大面積のポリゴンの重心」にしている。単純な平均だと、
離島を多く持つ区域でピンが海上に落ちるため（`tool/build_assets.py`）。

`DisasterEvent.latitude` を nullable にして、`hasLocation` が false のものは
一覧に「地図なし」と添えて必ず現れるようにした。**地図に出せないことを、
情報を捨てる理由にしない**というのがここでの方針。

## 3. サーバーを持たない

中継サーバーを立てれば、CORS も認証もレート制限も自由に扱える。
が、個人で続けるには運用費と手間が重い。

そこで **CORS が許可されている取得先だけを選んだ**。
実際に `Access-Control-Allow-Origin` を確認してからソースを決めている。

| 検討したが採らなかったもの | 理由 |
|---|---|
| ReliefWeb API | appname の事前申請が必要 |
| GDACS | エンドポイントによって CORS の扱いが不安定 |
| CARTO のベースマップ | API キーが必要になり、地図に透かしが入る |
| FCM によるプッシュ通知 | 送信側にサーバーが要る |

通知は「端末が15分ごとに自分で取りに行き、条件に合えば自分で鳴らす」方式にした。
これならサーバーが要らない。代わりに**即時性は15分刻みが上限**になる
（Android WorkManager の最短間隔）。速さが要る用途は GitHub Actions 側の
定期監視（`tool/watch.py`）で補う、という役割分担にしている。

## 4. 失敗したときに何を見せるか

災害情報は「取れなかった」ことが分からないのが一番まずい。

- 1つのソースが落ちても、他のソースの結果は表示する
- ただし**どのソースが落ちたかを画面に出す**（`DisasterSnapshot.failures`）
- 全部落ちたらキャッシュを出し、**「保存済みの情報です」と明示**する
- 日本の地震だけは、P2P地震情報が落ちたときに気象庁の一覧へ切り替える
  （一次情報源だが 600KB あるので、平常時は叩かない）

## 5. 検証を外部 API に依存させない

各 API の実際の応答を `test/fixtures/` に保存し、パーサはそれに対してテストする。
ネットワークが要らないので CI で安定して回り、
`tool/refresh_fixtures.sh` で取り直したときに**仕様変更があればテストが落ちる**。

特に落としたくない間違いを名指しでテストしている。

- GeoJSON の `[経度, 緯度]` を取り違えていないか
- 日本時間を UTC に直しているか（9時間ずれ）
- 気象庁の続報が並んでいるとき、同じ地震を重複させていないか
- 区域コードから座標を引けているか（引けないと地図から消える）

---

## 6. Web で踏んだこと

- **日本語フォントを同梱していないと、初回表示が豆腐（□）になる。**
  さらに悪いことに、文字幅の計算が実際の描画とずれるため、
  チップやボタンのラベルが途中で欠ける（英語ラベルでは起きない）。
  4.5MB 増えるが Noto Sans JP を同梱して解決した。
- **Slack などの Incoming Webhook はブラウザから直接叩けない**（CORS 非対応）。
  Web版では送信内容を提示するにとどめ、実送信はアプリ版か GitHub Actions に任せている。
